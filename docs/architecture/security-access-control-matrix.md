# Security Access Control Matrix

HeartStone applies **default-deny session authentication** across the HTTP API. Every controller route is protected unless explicitly opted out with `@Public()`. This document is the human-readable security matrix; the machine-readable source of truth is [`security/protected-route-manifest.json`](../../security/protected-route-manifest.json), generated by [`scripts/generate-protected-route-manifest.ts`](../../scripts/generate-protected-route-manifest.ts).

## Security architecture overview

| Layer | Mechanism | Behavior |
|---|---|---|
| Global guard | `SessionAuthGuard` registered as `APP_GUARD` in `SecurityModule` | All routes require a valid Bearer session token unless marked public |
| Opt-out | `@Public()` decorator (`IS_PUBLIC_KEY`) | Skips session validation for explicitly designated handlers or controller classes |
| Actor context | `ActorContextService`, `CaseAccessService`, domain services | Authentication establishes identity only; scoped access is enforced per domain |
| Authority (Phase 4+) | `AuthorityPolicyGuard` + `@RequiresAuthority()` | Consequential actions require explicit function authority evaluation |
| Audit | Security and domain audit services | Sensitive reads and writes remain attributable to session identity |

**Primary platform invariant:** User ≠ Officeholder ≠ Role ≠ Permission ≠ Authority. Authentication proves identity; it does not confer government decision authority.

## Route classification legend

| Route class | Auth required | Typical actor | Meaning |
|---|---|---|---|
| `PUBLIC` | No | Anonymous | Explicitly public endpoints (login, catalog discovery, verification codes) |
| `SYSTEM/HEALTH` | No | Monitor / load balancer | Process health, readiness, and version probes with no domain data |
| `AUTHENTICATED_SELF_SERVICE` | Yes | Citizen, applicant, holder | Session-scoped self-service (own applications, applicant timelines, document custody) |
| `AUTHENTICATED_INSTITUTIONAL` | Yes | Official with case/institutional scope | Institutional operations on cases, evidence governance, compliance dashboards |
| `RESTRICTED_ADMINISTRATIVE` | Yes | Platform or structure administrator | Configuration of government structure, identity administration, intelligence, catalog admin |
| `CONSEQUENTIAL_AUTHORITY_CONTROLLED` | Yes | Authorized officeholder | Decisions and issuance actions requiring explicit authority evaluation |

Regenerate the manifest after controller changes:

```bash
npm run security:manifest
# or
./node_modules/.bin/ts-node scripts/generate-protected-route-manifest.ts
```

## Domain: identity

| Field | Value |
|---|---|
| Route class | `RESTRICTED_ADMINISTRATIVE` (admin CRUD); `AUTHENTICATED_SELF_SERVICE` for `/identity/me` and `/identity/auth/logout`; `PUBLIC` for `/identity/auth/login` |
| Auth requirement | Session Bearer token on protected routes; login is public |
| Scope | Identity administration or authenticated self profile |
| Authority | None from identity alone — `AuthorityBoundaryService` blocks authority inference |
| Actor source | Session identity; administrators for provisioning endpoints |
| Primary invariant | User != Officeholder != Role != Permission != Authority |

Key routes: person/user-account/credential provisioning (administrative), `GET /identity/me` (self-service profile), `POST /identity/auth/login` (public), `POST /identity/auth/logout` (authenticated).

## Machine-readable manifest

The manifest enumerates every scanned controller route with:

- `path`, `method`, `domain`, `controller`, `sourceFile`, `handler`
- `routeClass`, `authenticationRequired`, `isPublic`
- `scopeRequirement`, `authorityRequirement`, `actorSource`, `primarySecurityInvariant`
- `routeCount` and per-class `summary` counts

Use the manifest for CI regression (`src/security/protected-route-manifest.spec.ts`, `test/security-regression.e2e-spec.ts`) and for diff review when adding controllers or changing access posture.
